### Executive Summary

### Vision
Create India's first comprehensive agricultural services marketplace connecting farmers with equipment owners and skilled agricultural workers, enabling seamless booking, transparent pricing, and reliable service delivery.

### Mission
Digitize agricultural service procurement by providing a platform where farmers can easily access tractors, equipment, and skilled labor while enabling service providers to maximize their asset utilization and income.

### Key Value Propositions
- **For Farmers**: Easy access to equipment and skilled labor, transparent pricing, reliable service delivery
- **For Service Providers**: Increased asset utilization, steady income, reduced customer acquisition costs
- **For Platform**: Transaction-based revenue model with scalable operations

### Business Model
Commission-based marketplace (10-15% per transaction) similar to Uber/Ola, focusing on agricultural services in rural India.

---


### Target Geographic Market

#### Launch Districts (Priority Order)
1. **Nizamabad & Kamareddy** (Pilot districts)
2. **Medak** (High agricultural activity)
3. **Karimnagar** (Major farming hub)
4. **Mahabubnagar** (Large agricultural area)
5. **Warangal** (Diverse crop patterns)
6. **Jagtial** (Intensive farming)
7. **Adilabad** (Cotton belt)

#### Market Characteristics per District
- **Nizamabad**: 1,823 villages, 95% agricultural households, major crops: paddy, turmeric, sugarcane
- **Karimnagar**: 1,142 villages, strong cooperative presence, mechanization rate: 65%
- **Medak**: 1,100 villages, water-intensive crops, high tractor density

#### Competitive Advantages
- Mobile-first approach for rural users
- Bilingual support (Telugu/English)
- Local partnership network
- Transparent pricing and ratings

## User Personas & Journey

### Primary Personas

#### Persona 1: Ramesh - Small Farmer (Service Seeker)
- **Demographics**: Age 35-45, owns 3-5 acres, smartphone user
- **Pain Points**: Difficulty finding reliable equipment/labor, price negotiation hassles, seasonal availability issues
- **Goals**: Complete farming operations on time, reduce costs, ensure quality work
- **Technology Comfort**: Moderate, uses WhatsApp, basic apps

#### Persona 2: Suresh - Tractor Owner (Service Provider)
- **Demographics**: Age 30-50, owns 1-2 tractors, provides custom services
- **Pain Points**: Finding customers, idle equipment during off-season, payment delays
- **Goals**: Maximize equipment utilization, steady income, expand customer base
- **Technology Comfort**: Basic to moderate, willing to learn for business growth

#### Persona 3: Kumar - Agricultural Labor (Service Provider)
- **Demographics**: Age 25-55, skilled in specific operations, seasonal work
- **Pain Points**: Irregular work, low bargaining power, transportation to work sites
- **Goals**: Consistent work opportunities, fair wages, skill recognition
- **Technology Comfort**: Basic, needs simple interface

### User Journey Maps

#### Farmer Journey (Service Seeker)
1. **Discovery**: Opens app, sees available services in area
2. **Search**: Filters by service type, date, budget
3. **Compare**: Views provider profiles, ratings, pricing
4. **Book**: Creates service request or accepts quote
5. **Track**: Monitors service provider location/status
6. **Receive**: Service delivered and verified
7. **Pay**: Secure payment through escrow
8. **Rate**: Provides feedback and rating

#### Service Provider Journey
1. **Registration**: Profile creation, document verification
2. **Setup**: Service offerings, pricing, availability
3. **Discovery**: Receives nearby service requests
4. **Quote**: Submits competitive bids or accepts fixed pricing
5. **Accept**: Confirms booking and service details
6. **Deliver**: Performs service, updates status
7. **Complete**: Job completion verification
8. **Payment**: Receives payment minus platform commission


- **Primary Language**: .Net or Node.js with TypeScript

#### Infrastructure
- **Cloud Platform**: AWS or Azure
- **Container Orchestration**: Docker with Kubernetes
- **CI/CD**: GitHub Actions

#### Third-party Integrations
- **Payment Gateways**: Razorpay, UPI APIs
- **Maps & Location**: Google Maps API, Mapbox
- **SMS/OTP**: Twilio, AWS SNS
- **Push Notifications**: Firebase Cloud Messaging

### Scalability Considerations

#### Performance Requirements
- **Response Time**: < 3 seconds for API calls
- **Concurrent Users**: Support 1,000+ concurrent users
- **Database**: Handle 10,000+ transactions per day
- **File Upload**: Support image/video uploads up to 10MB

#### Security Requirements
- **Data Encryption**: AES-256 for data at rest, TLS 1.3 for data in transit
- **Authentication**: Multi-factor authentication for sensitive operations

## Database Schema

### Core Entities

#### Users Table
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone_number VARCHAR(15) UNIQUE NOT NULL,
    email VARCHAR(255),
    full_name VARCHAR(255) NOT NULL,
    date_of_birth DATE,
    gender ENUM('male', 'female', 'other'),
    profile_image_url VARCHAR(500),
    address TEXT,
    district VARCHAR(100),
    mandal VARCHAR(100),
    village VARCHAR(100),
    pincode VARCHAR(10),
    aadhaar_number VARCHAR(12),
    is_verified BOOLEAN DEFAULT FALSE,
    user_type ENUM('seeker', 'provider', 'both') NOT NULL,
    status ENUM('active', 'inactive', 'suspended') DEFAULT 'active',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Services Table
```sql
CREATE TABLE services (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    provider_id UUID REFERENCES users(id),
    category_id UUID REFERENCES service_categories(id),
    title VARCHAR(255) NOT NULL,
    description TEXT,
    pricing_model ENUM('hourly', 'per_acre', 'daily', 'monthly', 'fixed') NOT NULL,
    base_price DECIMAL(10,2) NOT NULL,
    max_price DECIMAL(10,2),
    service_radius INTEGER DEFAULT 25, -- in kilometers
    equipment_required BOOLEAN DEFAULT FALSE,
    equipment_provided BOOLEAN DEFAULT FALSE,
    operator_provided BOOLEAN DEFAULT FALSE,
    availability_calendar JSON, -- {date: available_hours}
    minimum_booking_hours INTEGER DEFAULT 1,
    advance_booking_days INTEGER DEFAULT 30,
    cancellation_policy TEXT,
    terms_conditions TEXT,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Service Categories Table
```sql
CREATE TABLE service_categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    name_telugu VARCHAR(255),
    description TEXT,
    icon_url VARCHAR(500),
    parent_category_id UUID REFERENCES service_categories(id),
    sort_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### Bookings Table
```sql
CREATE TABLE bookings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    seeker_id UUID REFERENCES users(id),
    provider_id UUID REFERENCES users(id),
    service_id UUID REFERENCES services(id),
    booking_type ENUM('direct', 'bidding') NOT NULL,
    farm_location POINT NOT NULL, -- GPS coordinates
    farm_address TEXT,
    area_acres DECIMAL(8,2),
    scheduled_date DATE NOT NULL,
    scheduled_start_time TIME,
    scheduled_end_time TIME,
    actual_start_time TIMESTAMP,
    actual_end_time TIMESTAMP,
    quoted_amount DECIMAL(10,2) NOT NULL,
    final_amount DECIMAL(10,2),
    platform_fee DECIMAL(8,2),
    payment_status ENUM('pending', 'held', 'released', 'refunded') DEFAULT 'pending',
    booking_status ENUM('requested', 'accepted', 'in_progress', 'completed', 'cancelled', 'disputed') DEFAULT 'requested',
    special_instructions TEXT,
    cancellation_reason TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### Bids Table
```sql
CREATE TABLE bids (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    booking_id UUID REFERENCES bookings(id),
    provider_id UUID REFERENCES users(id),
    quoted_amount DECIMAL(10,2) NOT NULL,
    estimated_duration_hours INTEGER,
    additional_charges TEXT,
    bid_message TEXT,
    bid_status ENUM('pending', 'accepted', 'rejected', 'expired') DEFAULT 'pending',
    expires_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### Reviews Table
```sql
CREATE TABLE reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    booking_id UUID REFERENCES bookings(id),
    reviewer_id UUID REFERENCES users(id),
    reviewee_id UUID REFERENCES users(id),
    rating INTEGER CHECK (rating >= 1 AND rating <= 5),
    review_text TEXT,
    review_images JSON, -- array of image URLs
    response_text TEXT, -- response from reviewee
    is_anonymous BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### Payments Table
```sql
CREATE TABLE payments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    booking_id UUID REFERENCES bookings(id),
    payer_id UUID REFERENCES users(id),
    payee_id UUID REFERENCES users(id),
    payment_gateway VARCHAR(50) NOT NULL,
    gateway_transaction_id VARCHAR(255),
    gross_amount DECIMAL(10,2) NOT NULL,
    platform_fee DECIMAL(8,2) NOT NULL,
    net_amount DECIMAL(10,2) NOT NULL,
    payment_method VARCHAR(50),
    payment_status ENUM('initiated', 'successful', 'failed', 'refunded') DEFAULT 'initiated',
    escrow_status ENUM('held', 'released', 'disputed') DEFAULT 'held',
    processed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Indexes and Performance Optimization

```sql
-- Location-based search optimization
CREATE INDEX idx_users_location ON users USING GIST(ST_Point(longitude, latitude));
CREATE INDEX idx_bookings_farm_location ON bookings USING GIST(farm_location);

-- Status-based queries
CREATE INDEX idx_bookings_status_date ON bookings(booking_status, scheduled_date);
CREATE INDEX idx_services_active_category ON services(is_active, category_id);

-- User performance
CREATE INDEX idx_users_phone_verified ON users(phone_number, is_verified);
CREATE INDEX idx_reviews_rating_user ON reviews(reviewee_id, rating);
```

Enhancement Recommendations:


Normalize Location Data: The users table uses VARCHAR for district, mandal, and village. This can lead to spelling errors and inconsistent data (e.g., "Nizamabad" vs. "Nizambad").

Schema Change: Create districts, mandals, and villages tables with predefined names. Use foreign key IDs in the users table. This standardizes location data, making location-based matching far more accurate and reliable.


Enhance Farm Location Data: The bookings table uses a POINT for farm_location. While good, a single point doesn't capture the area of a farm.

Future-Proofing: Consider using a geospatial data type like POLYGON (available with extensions like PostGIS in PostgreSQL). This would allow farmers to draw their farm boundary on the map, leading to more accurate area calculations and eliminating disputes over the size of the job.
